# Веб-консоль

Parent: [[Index]]

## Назначение

Сервис `barkdocs-admin` — веб-консоль BarkDocs с серверным рендерингом (axum + maud). Пользователи сами регистрируются, выпускают ключи MCP для своих агентов и видят использование только своих ключей. Администратор видит использование всей системы и отдельных пользователей, управляет пользователями и библиотеками документации. Своего хранилища нет: аккаунты и ключи — в [[Auth/AuthService|AuthService]], библиотеки и статистика — в [[Engine/DocsEngine|движке]].

## Источники

| Файл | Значимый символ | Роль |
|------|-----------------|------|
| `backend/barkdocs-admin/src/main.rs` | `router`, `security_headers` | Маршруты, CSP и запрет кэширования страниц |
| `backend/barkdocs-admin/src/session.rs` | `CurrentUser`, `AdminUser` | Сессия из cookie через `GET /me` auth; проверка роли |
| `backend/barkdocs-admin/src/session.rs` | `csrf_guard`, `redirect_with`, `consume_flash` | Защита форм, сообщения после редиректа |
| `backend/barkdocs-admin/src/client.rs` | `Services` | Клиенты `barkdocs-auth` и `barkdocs-engine` |
| `backend/barkdocs-admin/src/views.rs` | `page`, `usage`, `daily_chart`, `connect_instructions` | Макет, блок статистики, график по дням, инструкция подключения |
| `backend/barkdocs-admin/src/pages/` | `overview`, `keys`, `libraries`, `users`, `account` | Страницы консоли |
| `backend/barkdocs-admin/static/` | `app.css`, `app.js` | Стили и подтверждение опасных действий; встраиваются в бинарник |

## Страницы и права

| Путь | Кому | Что делает |
|------|------|------------|
| `/login`, `/register`, `/logout` | Все | Вход, регистрация (если разрешена), выход |
| `/` | Вошедшие | Использование: пользователь — свои ключи; администратор — вся система или `?scope=me` |
| `/keys` | Вошедшие | Выпуск и отзыв своих ключей, инструкция подключения агента |
| `/account` | Вошедшие | Профиль и смена пароля |
| `/libraries`, `/libraries/new` | admin | Список библиотек; добавление автоматически (пакет или ссылка) или вручную с источниками |
| `/library?id=` | admin | Свойства, источники, синхронизация, удаление, пробный поиск, статистика библиотеки |
| `/users`, `/users/{id}` | admin | Пользователи с потреблением; ключи, статистика, блокировка и роль пользователя |

Период статистики задаётся `?days=` (7, 30, 90, 365, 0 — всё время).

## Зависимости и взаимодействия

- [[Auth/AuthService|AuthService]]: вход (`POST /sessions`), регистрация, `GET /me` на каждый запрос, ключи и пользователи. Права на ключи и пользователей auth проверяет сам по токену сессии.
- [[Engine/DocsEngine|DocsEngine]]: `GET /stats`, управление библиотеками и источниками, пробный поиск `GET /docs` с каналом `web`. Движок не проверяет права: роль admin проверяет консоль до вызова.
- Адрес MCP для инструкций — `MCP_PUBLIC_URL`; консоль сама MCP не обслуживает.

## Ограничения и важные детали

- Адрес по умолчанию `0.0.0.0:8083`. Обязательные переменные: `AUTH_URL`, `ENGINE_URL`. Необязательные: `MCP_PUBLIC_URL`, `ALLOW_REGISTRATION` (показывать регистрацию; запрет действует в auth), `COOKIE_SECURE`.
- Cookie сессии `bd_session`: HttpOnly, SameSite=Strict, Secure при `COOKIE_SECURE=true` или `X-Forwarded-Proto: https`.
- Формы, кроме GET, принимаются только при `Sec-Fetch-Site` `same-origin`/`none`; без него сверяется `Origin` с `Host`. `Origin` у форм бывает `null`, поэтому решает `Sec-Fetch-Site`.
- CSP запрещает инлайн-стили и скрипты: высоты столбиков графика и долей задаются классами `.h-N`/`.w-N`, сгенерированными при старте.
- Новый ключ показывается прямо в ответе на POST и больше нигде: не попадает ни в URL, ни в cookie.
- Ошибки форм показываются flash-сообщением из короткоживущей cookie `bd_flash` либо повторным рендером формы с введёнными значениями.

## Решения и основания

- Консоль без своего хранилища, права ключей и пользователей проверяет auth. Основание: в auth уже хранятся ключи; консоль передаёт токен сессии, и пользователь не получит чужие ключи даже при ошибке в консоли.
- Ключи агентов не наследуют роль admin. Основание: утечка ключа агента не должна давать права на изменение индекса; администрирование — через консоль или мастер-ключ.
