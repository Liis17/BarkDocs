# Учёт запросов

Parent: [[Index]]

## Назначение

Журнал обращений агентов к документации и статистика по нему для [[Admin/AdminConsole|веб-консоли]]. Ограничений на число запросов нет: журнал нужен только для учёта.

## Источники

| Файл | Значимый символ | Роль |
|------|-----------------|------|
| `backend/barkdocs-engine/src/usage.rs` | `Caller` | Кто спрашивает: заголовки `x-barkdocs-user-id`, `x-barkdocs-key-id`, `x-barkdocs-channel` |
| `backend/barkdocs-engine/src/usage.rs` | `Record`, `record` | Запись `resolve` и `docs` в фоне |
| `backend/barkdocs-engine/src/usage.rs` | `stats` | `GET /stats` |
| `backend/barkdocs-engine/migrations/0002_usage.sql` | `requests` | Журнал в схеме `engine` |

## Публичные контракты

`GET /stats?user_id=&key_id=&library_id=&days=` — все фильтры необязательны; `days` по умолчанию 30, 0 — всё время, максимум 365. Ответ:

- `totals` — за всё время с учётом фильтров: запросы, `docs`, `resolve`, объём, сегодня (UTC), за период, число пользователей, ключей и библиотек;
- `daily` — ряд по дням за период без пропусков (для «всего времени» — 90 дней);
- `libraries`, `keys`, `users`, `queries`, `pages`, `channels` — разбивки за период;
- `recent` — 50 последних запросов.

## Что записывается

Каждый `GET /libraries/resolve` и `GET /docs` движка: время, пользователь и ключ (если есть), канал (`mcp`, `api`, `web`), тип, библиотека, текст запроса, число найденных фрагментов, объём ответа в символах и уникальные URL выданных страниц. Консоль оценивает токены как символы / 4.

## Зависимости и взаимодействия

- Заголовки ставит [[Web/Gateway|шлюз]] по ответу `POST /verify` и [[Admin/AdminConsole|консоль]] для пробного поиска. Движок доверяет им, потому что доступен только из внутренней сети.
- Вызывается из обработчиков `resolve` и `docs` в `backend/barkdocs-engine/src/api.rs`.

## Ограничения и важные детали

- Запись идёт в `tokio::spawn`: не задерживает ответ, а сбой записи только логируется.
- Библиотека хранится по slug без внешнего ключа: статистика переживает удаление библиотеки.
- Журнал не очищается; индексы по `at`, `(user_id, at)`, `(key_id, at)`, `(library, at)`.
- Запрос к несуществующей библиотеке (404) не записывается.
