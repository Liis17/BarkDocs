# Движок документации

Parent: [[Index]]

## Назначение

Внутренний сервис `barkdocs-engine`: хранит библиотеки, источники и чанки, отвечает на поиск, запускает синхронизацию по расписанию и по запросу. Авторизации не имеет; наружу его публикует только [[Web/Gateway|шлюз]]. Регистрацию библиотек по именам и ссылкам делает [[Engine/Discovery|Поиск библиотек]], загрузку — [[Engine/Sources|Источники]].

## Источники

| Файл | Значимый символ | Роль |
|------|-----------------|------|
| `backend/barkdocs-engine/src/main.rs` | `main`, `AppState` | Запуск, схема `engine`, миграции, планировщик |
| `backend/barkdocs-engine/src/api.rs` | `router`, `docs`, `resolve`, `add_library`, `sync_library` | Внутренний HTTP API |
| `backend/barkdocs-engine/src/db.rs` | `search_chunks`, `search_libraries`, `replace_chunks` | Запросы к БД, FTS-поиск |
| `backend/barkdocs-engine/src/db.rs` | `claim_source`, `mark_unchanged`, `mark_failed` | Блокировка и статусы источников |
| `backend/barkdocs-engine/src/sync.rs` | `scheduler`, `spawn_sync`, `sync_source`, `run` | Планировщик и синхронизация |
| `backend/barkdocs-engine/src/chunk.rs` | `chunk_markdown` | Нарезка markdown на чанки |
| `backend/barkdocs-engine/migrations/0001_init.sql` | `libraries`, `sources`, `chunks` | Схема `engine` |

## Публичные контракты (внутренний HTTP, `BIND_ADDR`, по умолчанию `0.0.0.0:8082`)

| Контракт | Поведение и условия |
|----------|---------------------|
| `GET /libraries/resolve?name=` | Поиск в индексе; если точного совпадения нет, опрашивает реестры. Статусы: `ready`, `indexing`, `failed` |
| `POST /libraries` (`url` или `name`, ровно одно) | 201 со списком библиотек. 404, если источников не найдено; 502 при ошибке регистрации |
| `POST /sync` (`library_id`) | 202 со счётчиком источников. 404, если библиотеки нет |
| `GET /docs?library_id=&query=&limit=` | `{library, results}`. Запрос 1–1000 символов, иначе 422. `limit` по умолчанию 10, диапазон 1–50 |

`library_id` — это slug вида `/owner/repo` для GitHub или `/host/path` для сайтов.

## Хранение и поиск

- `libraries` — метаданные; `sources` — `kind` ∈ {`github`, `llms`, `site`}, уникальны в паре библиотека + `kind` + `url`; `chunks` — текст с `tsvector` (заголовок с весом A, `english`).
- Запрос переводится через `websearch_to_tsquery`, затем пробелы-`&` заменяются на `|`. Слова объединяются через OR, фразы в кавычках остаются фразами. Ранжирование — `ts_rank_cd`.
- Статус библиотеки вычисляется из данных: `ready` — есть чанки; `indexing` — есть источники, которые синхронизируются или ещё не проверялись; иначе `failed`.

## Синхронизация

- Планировщик раз в час выбирает источники с `next_check_at <= now()`. Сроки хранятся в БД, поэтому перезапуск их не сбивает.
- `claim_source` ставит `sync_started_at` атомарно; метка старше часа считается следом упавшего процесса.
- Одновременно синхронизируется не более 4 источников (семафор).
- Успех: следующая проверка через 24 часа. Ошибка: через 1 час. Пустой результат «документация не найдена»: через 24 часа.
- Пустой результат не записывается: старый индекс остаётся.
- `replace_chunks` удаляет и вставляет чанки в одной транзакции.

## Нарезка на чанки

`chunk_markdown` делит документ по заголовкам уровней `#`–`###`; более мелкие остаются внутри раздела. Длина чанка ограничена 6000 символами. Front matter удаляется, ссылки в заголовках заменяются текстом.

## Зависимости и взаимодействия

- Использует [[Engine/Discovery|Поиск библиотек]], [[Engine/Sources|Источники]] и [[Engine/SafeHttp|Безопасный HTTP-клиент]].
- Используется [[Web/Gateway|шлюзом]] и [[Web/McpServer|MCP-сервером]].

## Ограничения и важные детали

- Схема `engine`, миграции `sqlx::migrate!()` выполняются при старте.
- Токен `GITHUB_TOKEN` необязателен; без него лимит GitHub API 60 запросов в час, и это логируется при старте.
- Новый `kind` источника требует изменения `CHECK` в миграции и `sources::fetch`.

## Решения и основания

- Поиск через OR. Основание: комментарий в `db.rs` — при AND вопрос на естественном языке почти ничего не находит; ранжирование поднимает лучшие совпадения.
- Атомарная замена чанков. Основание: комментарий в `db.rs` — поиск не должен видеть частичный индекс.
- Пустой результат не заменяет индекс. Основание: комментарий в `sync.rs` — пустой результат почти всегда сбой или смена вёрстки.
- Выбор статуса через данные, а не отдельное поле. Основание не задокументировано.
- Выбор PostgreSQL FTS вместо внешнего поискового движка. Основание не задокументировано.
